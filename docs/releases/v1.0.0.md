# EnvDeck 1.0.0

The first release of EnvDeck, a desktop app for macOS and Windows that finds the `.env` and
other config files spread across your projects, shows them with secrets masked, and gets them
where you need them.

## Highlights

- **Finds what git ignores.** Scans your code folders for `.env`, `.env.*`, `*.env`, `.npmrc`,
  `appsettings*.json`, `application*.yml`, `docker-compose*.yml`, `.vscode/launch.json` and
  more, grouped by project. `node_modules`, `bin`, `obj`, `target` and similar folders are
  skipped. Changes you make in your editor show up right away.
- **Secrets stay masked** in the table, the source view and comparisons until you reveal them.
- **Copy it out** the way you need it:
  - the file's contents, or selected variables as `export`, PowerShell, `cmd`, JSON or `docker -e`
  - the file itself, to paste into Finder, Explorer or the VS Code explorer, or drag it there
  - **Copy to…** another project. If the file already exists there, you choose what happens:
    stop, back up the old file, keep both, merge or replace.
- **Keep files in sync.** Compare a `.env` with its `.env.example` and add the missing keys,
  send variables to another `.env`, or create a `.env` from a template. Edits keep comments,
  key order, `export` prefixes and CRLF line endings.
- **Push to GitHub.** Send keys from a `.env` to a repository's Actions secrets and variables,
  including environment secrets. It uses your existing GitHub CLI login (`gh auth login`), so
  it works on organization repositories without an owner approving an app.
- **Push to Azure App Service.** Send keys to an app's settings, connection strings, general
  settings or Deployment Center, on the app or a deployment slot. It uses your existing Azure
  CLI login (`az login`). Existing settings are kept; EnvDeck never deletes any.
- **In-app updates.** EnvDeck checks this repository's releases at launch and from
  **Settings ▸ Check for updates…**. It installs signed updates and restarts.
- **Open in your editor:** VS Code, VS Code Insiders, Cursor or Windsurf.
- **Keyboard shortcuts** for filtering (⌘K / Ctrl+K), rescanning, copying and saving.
- A short tour opens on first launch; **Settings ▸ Show tutorial** opens it again.

## Your files stay yours

EnvDeck has no database and keeps no data of its own. Files are read fresh from disk. The only
file it writes for itself is `~/.envdeck.json`, and only when you save a folder, remove one or
pick a library folder. It's plain JSON you can edit by hand. Values are never logged.

Apart from the update check, EnvDeck connects to the internet only when you push to GitHub or
Azure, through the `gh` and `az` command-line tools.

## Install

| OS | File |
| --- | --- |
| macOS (Apple silicon and Intel) | `EnvDeck_1.0.0_universal.dmg` |
| Windows | `EnvDeck_1.0.0_x64-setup.exe` (recommended) or `EnvDeck_1.0.0_x64_en-US.msi` |

- Windows needs WebView2; the installer downloads it if it's missing.
- **The installers aren't code-signed yet,** so you have to confirm the first launch:
  - **macOS:** right-click EnvDeck in Applications and choose **Open**, or allow it in
    **System Settings ▸ Privacy & Security**.
  - **Windows:** in the SmartScreen prompt, choose **More info ▸ Run anyway**.
- Push to GitHub needs the [GitHub CLI](https://cli.github.com), and Push to Azure needs the
  [Azure CLI](https://aka.ms/azcli). The rest of EnvDeck works without either.

## Known limitations

- Linux isn't supported.
- JSON and YAML files open in the source view; there's no tree view yet.
- EnvDeck doesn't create GitHub environments. **Manage environments** opens the repository's
  settings page instead.
